1. Market Basket Analysis (MBA)

Market Basket Analysis is a data mining technique used to discover patterns and relationships between items frequently purchased together. It is based on Association Rule Mining and is widely used in retail, e-commerce, and recommendation systems.

Real-World Example

If many customers who buy Bread also buy Butter, a retailer can:

  • Place Bread and Butter close together in the store.
  • Offer a discount on Butter when Bread is purchased.
  • Recommend Butter to online shoppers who add Bread to their cart.

Key Concepts

Transactional Dataset
Each row = one transaction. Each transaction = set of items bought together.
Example:
Transaction IDItems Bought
T1Milk, Bread, Butter
T2Milk, Bread
T3Bread, Butter, Jam
T4Milk, Butter
Association Rule
A rule written as A ⇒ B, meaning "if a customer buys A, they are likely to also buy B."
Example: {Bread} ⇒ {Butter}
Itemset
A collection of one or more items. A frequent itemset is one that appears in at least a minimum number of transactions (≥ min support).

Applications of MBA

🏬 Retail

Optimize product placement, design combo offers (burger + fries + drink).

🛍️ E-commerce

Amazon's "Customers who bought this also bought..." recommendation engine.

🏥 Healthcare

Analyze prescription patterns, detect potential drug interactions.

💳 Finance

Identify fraudulent transactions based on unusual purchase patterns.

📱 Telecom

Bundle mobile services based on customer preferences.

🎬 Streaming

Netflix and Spotify recommend content based on viewing/listening history.

2. Key Metrics — Support, Confidence & Lift

These three metrics measure the strength and significance of association rules. Always memorize these — they appear in every exam question.

1. Support

Measures how frequently an itemset appears across all transactions. Tells us if the rule is based on enough data.

Formula
Support(A⇒B)= Transactions containing both A and B / Total Transactions
Support(A)= Transactions containing A / Total Transactions
Example 5 total transactions. {Bread, Butter} appears in 2 → Support = 2/5 = 40%

2. Confidence

Measures how often the rule is correct. "Given A is bought, how likely is B also bought?" — it is the conditional probability of B given A.

Formula
Confidence(A⇒B)= Support(A and B) / Support(A)
Example Support({Milk, Bread}) = 40%, Support({Milk}) = 60% → Confidence = 40%/60% = 66.7%

3. Lift

Measures how much more likely B is purchased when A is purchased, compared to if A and B were independent. Lift corrects for item popularity.

Formula
Lift(A⇒B)= Confidence(A⇒B) / Support(B)
Lift > 1 ✅

A and B are positively correlated. Buying A increases likelihood of B.

Lift = 1 ⚪

A and B are independent. No relationship.

Lift < 1 ❌

A and B are negatively correlated. Buying A reduces likelihood of B.

3. Apriori Algorithm

The Apriori Algorithm is the most widely used algorithm for Association Rule Mining. It mines frequent itemsets iteratively from a transactional database using a bottom-up approach — starting from single items and building up to larger itemsets.

The Apriori Property (Anti-Monotone Property)

📌 Key Property — Must Remember "If an itemset is frequent, then ALL of its subsets must also be frequent."
Equivalently: "If a subset of an itemset is NOT frequent, then the entire itemset CANNOT be frequent."
This allows pruning — we can skip (prune) candidate itemsets that have infrequent subsets, greatly improving efficiency.

Steps of the Apriori Algorithm

Set Thresholds: Define minimum support and minimum confidence values before starting.
Generate Frequent 1-Itemsets (L1): Scan the database, count frequency of each individual item. Keep only items with support ≥ min_support.
Generate Candidate 2-Itemsets (C2): Combine all pairs from L1. Then scan the database to count their support.
Prune: Remove any candidate whose support < min_support. The remaining set = L2 (frequent 2-itemsets).
Repeat: Continue generating and pruning k-itemsets until no new frequent itemsets are found.
Generate Association Rules: From each frequent itemset, generate all possible rules. Keep only rules with confidence ≥ min_confidence.

Advantages & Disadvantages

✅ Advantages
  • Simple and easy to understand
  • Guaranteed to find all frequent itemsets
  • Pruning greatly reduces search space
❌ Disadvantages
  • Requires multiple scans of the dataset
  • Generates a large number of candidate itemsets
  • Slow for very large datasets

5. FP-Growth — Mining Without Candidate Generation

The FP-Growth (Frequent Pattern Growth) algorithm was designed to overcome the major bottleneck of Apriori — the need for candidate generation and multiple database scans. It uses a compact tree structure called an FP-Tree.

Why Avoid Candidate Generation?

The Apriori approach suffers from:

  • Multiple database scans — increases time complexity significantly.
  • Huge candidate sets — exponential number of candidate itemsets to check.
  • High memory usage — storing and checking all candidates is expensive.

FP-Growth solves this by compressing the entire database into an FP-Tree in just two scans, then mining frequent patterns directly from the tree.

How FP-Growth Works

First Database Scan: Count frequency of each item. Discard items below min_support. Sort remaining items in descending order of frequency.
Build FP-Tree: Second scan — insert each transaction into the tree. Common prefixes are shared, saving memory. Each node stores: item name + count.
Mine FP-Tree: For each item (starting from least frequent), find all its conditional pattern bases (prefix paths leading to that item in the tree).
Build Conditional FP-Tree: Construct a smaller FP-Tree for each item using its conditional pattern base.
Recursively Extract Patterns: Mine each conditional FP-Tree to extract frequent itemsets. No candidate generation needed at any step.

FP-Growth vs Apriori — Comparison

FeatureAprioriFP-Growth
Database ScansMultiple (one per itemset size)Only 2 scans
Candidate GenerationYes — expensiveNo — eliminated
Data StructureSimple listsFP-Tree (compressed)
SpeedSlow for large datasetsMuch faster
MemoryHigh (candidate sets)Lower (compressed tree)
Best Used ForSmall/medium datasetsLarge, dense datasets
Key Insight FP-Growth = 2 database scans + tree-based recursive mining. Apriori = k database scans for k-itemsets. FP-Growth is typically 10x–100x faster than Apriori on large databases.

6. ECLAT — Mining Using Vertical Data Format

ECLAT (Equivalence Class Clustering and Bottom-Up Lattice Traversal) mines frequent itemsets using a vertical data format, where instead of storing transactions as lists of items, each item stores the list of transaction IDs (TID set) in which it appears.

Horizontal vs Vertical Format

FormatStructureExample
HorizontalTransaction → ItemsT1: {A, B, C} | T2: {B, C, D}
Vertical (ECLAT)Item → TID setA: {T1} | B: {T1,T2} | C: {T1,T2} | D: {T2}
Key Advantage Support of any itemset = size of the intersection of its items' TID sets. No database scan needed — just set intersection!

7. Mining Closed Frequent Itemsets

Mining ALL frequent itemsets can generate an enormous number of itemsets — many of which are redundant. Closed Frequent Itemsets (CFIs) provide a compact, lossless representation.

Definition

📌 Closed Frequent Itemset (CFI) — Definition A frequent itemset X is closed if there is NO superset Y of X (i.e., Y ⊃ X) that has the same support as X.

In simple terms: X is closed if you cannot add any more item to X without reducing its support count.

Why Mine Closed Itemsets?

✔ Compact Representation

Significantly fewer itemsets to store — no redundancy.

✔ No Information Loss

All knowledge present in full frequent itemset mining is preserved.

✔ Faster Mining

Less computation time and memory usage.

✔ Simpler Rule Generation

Easier to generate association rules from a smaller set.

Complete Example (min_support = 2)

Transaction Database:

Transaction IDItems Bought
T1A, B, C
T2A, B
T3A, B, C, D
T4B, C, D
T5B, C

Step 1: All Frequent Itemsets (support ≥ 2):

ItemsetSupportClosed?Reason
{A}3❌ Not Closed{A,B} has same support (3)
{B}5❌ Not Closed{B,C} has same support (4) — wait, {B} support=5 ≠ {B,C} support=4, so actually closed. But {A,B} support=3 ≠ 5. So {B} is CLOSED. ✅
{C}4❌ Not Closed{B,C} has same support (4)
{D}2❌ Not Closed{B,D} or {C,D} may have same support
{A, B}3❌ Not Closed{A,B,C} has same support (2)? No — {A,B,C} support=2 ≠ 3. So {A,B} IS closed ✅
{B, C}4✅ ClosedNo superset has support = 4
{A, B, C}2✅ ClosedNo superset has support = 2
{B, C, D}2✅ ClosedNo superset has support = 2

{B, C}4
{A, B, C}2
{B, C, D}2
Quick Rule To check if X is closed: find all supersets of X. If any superset has the SAME support as X → X is NOT closed. If no superset matches → X IS closed.

8. Mining Multilevel Association Rules

Traditional association rule mining finds rules at a single level (e.g., {Milk} → {Bread}). But real-world data is often organized in hierarchies. Multilevel association rule mining discovers rules at different levels of abstraction.

Motivation Example

A product hierarchy might look like:

Food → Dairy Products → Milk → Low-Fat Milk
Food → Bakery Products → Bread → Whole Wheat Bread
Rule TypeExampleAbstraction Level
Single-Level{Milk} → {Bread}Item level
Multilevel (High){Dairy Products} → {Bakery Products}Category level
Multilevel (Low){Low-Fat Milk} → {Whole Wheat Bread}Sub-item level

Why Multilevel Rules?

  • More Insightful: Discovers both general trends and specific patterns.
  • Better Decision Making: Useful for inventory management, marketing, and recommendations.
  • Avoids Missing Patterns: Some patterns only appear at higher levels (individual items may not be frequent enough).

Approaches for Multilevel Mining

a) Top-Down Approach (Apriori-Based)
• Start mining at the highest (most general) level first.
• If a pattern is frequent at the top level, drill down to find more specific patterns.
• Uses different minimum support thresholds per level (MSD — Multiple Support Difference).
• Higher levels need higher support; lower levels need lower support.
Example: Min support for "Dairy Products" = 5%, for "Cheese" = 2%
b) Bottom-Up Approach (FP-Growth-Based)
• Start mining at the lowest (most specific) level first.
• Use generalization techniques to merge specific patterns into higher-level rules.
• Faster than top-down because it avoids candidate generation.
Example: {Whole Milk, Butter} → {Bread} generalized to {Dairy} → {Bakery}
💡 Key Challenge Higher-level items are more general and thus appear more frequently. Support thresholds must be adjusted per level to avoid trivial rules at higher levels and missing patterns at lower levels.

9. Mining Multidimensional Association Rules

Traditional association rule mining considers only items in transactions. Multidimensional Association Rule Mining incorporates multiple attributes (dimensions) such as age, gender, location, income, and time — giving much richer and more actionable insights.

Traditional vs Multidimensional Rules

Traditional Rule

{Milk, Bread} → {Butter}
(Support=30%, Confidence=80%)

Only items in the transaction are considered.

Multidimensional Rule

(Age=20-30, Gender=Male, Location=Urban) → (Buys=Sports Shoes)
(Support=15%, Confidence=70%)

Multiple customer attributes are used alongside items.

Types of Multidimensional Association Rules

1. Inter-Dimension Rules
Relationships between different dimensions.
Example: (Education=Graduate, Income=High) → (Buys=Luxury Car)
2. Hybrid-Dimension Rules
Mix of categorical attributes AND item-based transactions.
Example: (Age=25-40, Location=USA) → {Buys=Smartphone, Laptop}
3. Intra-Dimension Rules
Patterns within the same dimension.
Example: (Product Category=Electronics) → (Buys=Laptop, Smartphone)

Techniques for Multidimensional Mining

a) Generalized Apriori Algorithm
Treats categorical attributes as items. Prunes infrequent attribute combinations using the apriori property. Example rule: (Age=30-40, Income=Medium) → (Buys=Smartwatch) at Support=12%, Confidence=60%.
b) FP-Growth
Eliminates candidate generation. Constructs an FP-Tree across multiple dimensions. Much faster for large multidimensional datasets. Example: (Region=Asia, Payment=Credit Card) → (Buys=Smart TV) at Support=10%, Confidence=75%.
c) Constraint-Based Mining
Users apply specific constraints (age range, price range, location) to focus only on rules of interest. Reduces noise. Example: Only mine rules for customers aged 18-35, purchases above $500.
d) OLAP-Based Data Cube Approach
Store sales data in a multidimensional cube with dimensions like Time, Product, Location. Use drill-down (more specific) or roll-up (more general). Example: (Month=December, Location=USA) → (Buys=Winter Jackets) at Support=20%, Confidence=85%.

10. Correlation Analysis

Correlation Analysis measures the relationship between two or more variables in a dataset. It helps understand dependencies, identify trends, and improve decision-making. It plays a key role in feature selection, association rule mining, anomaly detection, and market analysis.

Types of Correlation

Positive Correlation ↗

Both variables increase together.
Example: More study time → Higher test score

Negative Correlation ↘

One increases, the other decreases.
Example: Higher car speed → Less travel time

No Correlation →

No meaningful relationship.
Example: Height vs. phone number

Measures of Correlation

a) Pearson Correlation Coefficient (r)
Measures linear correlation between two continuous variables.
Range: −1 to +1 where:
  • r = +1 → Perfect positive correlation
  • r = 0 → No correlation
  • r = −1 → Perfect negative correlation
Used when: Data is continuous and normally distributed.
b) Spearman's Rank Correlation (ρ)
Measures monotonic relationships (not necessarily linear).
Used when data is ordinal (ranked).
Formula: ρ = 1 − (6 Σd²ᵢ) / (n(n²−1)) where dᵢ = difference between ranks of corresponding values.
Used when: Data is ranked/ordinal or not normally distributed.
c) Chi-Square Test (χ²)
Used to find relationships between categorical variables.
Answers: "Are the two variables independent or related?"
Formula: χ² = Σ [(Observed − Expected)² / Expected]
Used when: Both variables are categorical (e.g., gender vs. product preference).
d) Kendall's Tau (τ)
Measures strength of ordinal associations between two variables.
Similar to Spearman's rank but more robust for small datasets with tied ranks.
Used when: Small dataset, many tied ranks, or when Spearman may be unreliable.

Quick Comparison Table

MethodData TypeMeasuresRange
Pearson (r)ContinuousLinear relationship−1 to +1
Spearman (ρ)Ordinal / RankedMonotonic relationship−1 to +1
Chi-Square (χ²)CategoricalIndependence / dependence0 to ∞
Kendall's Tau (τ)OrdinalOrdinal association−1 to +1

Applications of Correlation Analysis

Feature Selection

Identify most relevant attributes for machine learning models.

Market Basket Analysis

Find correlated products: laptops + mouse + keyboard.

Fraud Detection

Detect unusual patterns in financial transactions.

Healthcare

Identify correlations between lifestyle factors and diseases.

Stock Market

Find relationships between stock prices, inflation, and interest rates.

Social Sciences

Study relationships between socioeconomic factors and outcomes.

⚠️ Correlation vs Causation Correlation does NOT imply causation. Two variables can be correlated (e.g., ice cream sales and drowning rates both increase in summer) without one causing the other (both are caused by summer heat). Always interpret correlation carefully!

11. Constraint-Based Association Mining

Constraint-Based Association Mining is an advanced approach where users define specific constraints to focus the mining process on patterns of interest — instead of generating ALL possible rules (most of which may be irrelevant or useless).

Motivation Standard Apriori or FP-Growth generates thousands of rules. A store manager might only care about rules for electronics above $100. Constraints filter out uninteresting rules before or during mining, saving time and improving relevance.

Why Use Constraints?

  • Focus on relevant rules that match specific business needs.
  • Reduce computational complexity by pruning irrelevant itemsets early.
  • Handle large datasets efficiently — only compute what matters.
  • Give user control over the mining process.

Types of Constraints

1. Knowledge-Based Constraints
Use prior domain knowledge to restrict the search space.
Examples:
  • "Find associations only between electronic items."
  • "Ignore rules involving low-cost products."
2. Data Constraints
Based on attributes like price, quantity, category, or time.
Examples:
  • "Find associations only for transactions above $100."
  • "Consider purchases only from weekends."
3. Aggregate Constraints
Based on aggregated values like sum, count, or average across items.
Examples:
  • "Find product sets where the total price exceeds $200."
  • "Consider items that appear in at least 500 transactions."
4. Length Constraints
Controls the size (number of items) in generated itemsets or rules.
Examples:
  • "Find association rules with exactly 3 items."
  • "Exclude rules with more than 4 items."
5. Hierarchical Constraints
Mine at different levels of abstraction in category hierarchies.
Examples:
  • "Find associations between broad product categories (dairy, beverages) instead of individual items."
  • "Analyze patterns at brand level instead of product level."

Real-World Applications

🏬 Retail

Find patterns only in high-value transactions. Identify seasonal trends (summer vs winter).

🏥 Healthcare

Analyze disease patterns only for specific age groups. Find smoking & lung disease correlation.

💳 Fraud Detection

Detect fraudulent transactions above a threshold. Spot suspicious banking activity patterns.

🌐 Web Mining

Analyze trends only in specific geographic regions. Identify hashtags appearing 1000+ times.

Constraint-Based vs Standard Mining — Key Difference Standard mining: Generate ALL rules, then filter.  |  Constraint-based: Filter DURING mining. Constraint-based is more efficient because it prunes the search space early — irrelevant candidates are never even generated.

Quick Revision — Key Points to Remember

📐 Formulas
  • Support(A⇒B) = Txns(A∩B) / Total Txns
  • Confidence(A⇒B) = Support(A,B) / Support(A)
  • Lift(A⇒B) = Confidence(A⇒B) / Support(B)
  • Lift > 1 = positive correlation
🌳 Algorithms
  • Apriori: bottom-up, candidate generation, multiple scans
  • FP-Growth: 2 scans, FP-Tree, no candidates
  • ECLAT: vertical TID sets, set intersection
📌 Apriori Property
  • If X is frequent → all subsets of X are frequent
  • If subset of X is infrequent → X is infrequent (prune!)
  • This is also called Anti-Monotone Property
🔒 Closed Itemsets
  • X is closed if no superset has same support
  • Compact but lossless representation
  • Fewer itemsets, same knowledge
📈 Correlation
  • Pearson: linear, continuous data
  • Spearman: monotonic, ordinal data
  • Chi-Square: categorical data
  • Kendall's Tau: small datasets with ties
🔧 Constraint Types
  • Knowledge-based (domain rules)
  • Data constraints (price, time, category)
  • Aggregate constraints (sum, count, avg)
  • Length constraints (itemset size)
  • Hierarchical constraints (abstraction level)
